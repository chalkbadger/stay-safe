# Claude Code configuration meanings

Each report describes a settings file. Claude Code combines rules across its settings files and can apply session overrides. See [settings precedence] and [permission modes].

| Input | What the report can establish | Evidence |
|---|---|---|
| Settings file | The user settings file lives at `~/.claude/settings.json`. `CLAUDE_CONFIG_DIR` moves the folder. Explicitly selected settings are independent snapshots. The account and credential files are excluded. | [Settings locations], [account and credential files] |
| `permissions.defaultMode` | Lists the configured mode. `manual` is an alias for `default`. The built-in mode depends on surface and version. Project and project-local settings cannot enable `auto`. The reader leaves an absent mode and the decisions of the `auto` classifier unchecked. | [Modes], [starting mode], [Default mode] |
| `bypassPermissions` | Requests a mode that skips prompts. From v2.1.257, project and project-local settings cannot enable it. The file alone cannot establish the session mode. | [Default mode], [mode exceptions] |
| `permissions.allow` with `Bash` or `Bash(*)` | Both match all Bash commands. A more specific rule matches the commands covered by its pattern. A Bash allowance does not lift sandbox restrictions. | [Tool-wide rules], [Bash patterns], [sandbox and permissions] |
| Bare `WebFetch` | Covers all fetch requests. A bare allowance leaves the sandbox domain list unchanged. | [WebFetch rules] |
| `WebFetch(domain:…)` | Matches the specified domain pattern. `domain:*` covers every fetch domain from v2.1.172 and adds every host to the sandbox network allowlist from v2.1.186. Only the scope is shown. | [WebFetch rules], [sandbox network isolation] |
| `permissions.ask` and `permissions.deny` | A matching deny rule can block an allowed action. A matching ask rule can require approval. The report identifies the lists and leaves their matches unchecked. | [Rule order], [sandbox exceptions] |
| `sandbox.enabled` | A boolean configures Bash sandboxing. When omitted, the documented default is off. | [Sandbox default] |
| `sandbox.autoAllowBashIfSandboxed` | With sandboxing enabled, true requests automatic approval for eligible sandboxed Bash commands. False selects the regular permission flow. The omitted default changed from true to false in v2.1.324. | [Sandbox Bash approval] |
| Project settings file | Discovery also reads `.claude/settings.json` in the current folder, which Claude Code reads from the session's working directory. Its findings name that file. It is read even when the Claude Code folder is missing, and then a default run includes Claude Code. A project file that leaves out `permissions.defaultMode` or `sandbox.enabled` takes them from other files, so neither is reported for it. | [Project file location] |
| `hooks` | **Defined in:** any settings file; hooks merge across files. **Applies when:** the `disableAllHooks` value left after precedence across the files read isn't `true`, and the event is one Claude Code documents. **Can do:** a `command` hook runs a command, an `http` hook posts event data to a URL, an `mcp_tool` hook calls an MCP tool, and `prompt` and `agent` hooks ask a model. The catalog has one entry per kind per file (`hooks`, `hooks.http`, `hooks.prompt`, `hooks.agent`, `hooks.mcp_tool`), and each entry and finding names every handler by event, matcher group and position. Commands, `args`, URLs, prompts, `if` rules, matchers and undocumented event names are withheld; an undocumented event is a gap. MCP servers are outside reader coverage, so an `mcp_tool` hook that can run is a gap. | [hooks setting], [Hook events], [Hook handler types], [HTTP hooks] |
| Hooks on `PreToolUse` and `PermissionRequest` | **Defined in:** any settings file. **Applies to:** synchronous `command` and `http` handlers on these events. **Can do:** a `PreToolUse` hook can approve a call without a prompt and replace its input. A `PermissionRequest` hook can grant a permission, replace the input, add rules or change the mode. | [PreToolUse decisions], [PermissionRequest decisions] |
| Background command hooks | **Defined in:** a `command` handler's `async` or `asyncRewake` set to `true`, in any settings file. **Can do:** it runs in the background, and Claude Code doesn't wait for it, so its `decision`, `permissionDecision` and `continue` have no effect. It can't block, approve or rewrite the call it was triggered by. `asyncRewake` also runs in the background and wakes Claude on exit code 2. The finding is kept, without the decision capability. `async` applies only to `command` hooks. | [async field], [asyncRewake field], [Background hooks] |
| `if` on a hook | The rule is evaluated only on `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `PermissionRequest` and `PermissionDenied`. On other events a hook with `if` never runs, so it is listed as not running and gives no finding or gap. On tool events the finding says it runs only for matching tool calls. | [if field] |
| Exec form | With `args`, Claude Code spawns `command` directly with `args` as its arguments, so the Check names both. `args` must be a list of strings on a command hook; otherwise the handler is a gap. | [Command hook fields], [Exec form] |
| `prompt` and `agent` hooks | **Defined in:** any settings file. **Can do:** on `PreToolUse`, either can block the call or let normal processing continue. An agent hook can read, search and inspect files. On `PermissionRequest`, a prompt hook's `ok: false` has no effect, so the decision follows the normal flow. Claude Code skips agent hooks on that event. They are listed by kind and event, with no finding. | [Prompt hook events], [Prompt hook decisions], [Agent hooks] |
| `allowedHttpHookUrls` | Limits the URLs HTTP hooks can send to; arrays merge across settings files. It is listed with its patterns withheld. When a file read sets it, an HTTP hook's finding says the match wasn't checked; discovery applies this across the user and project files, and a `--config` file only to itself. | [allowedHttpHookUrls setting], [Limit HTTP hooks] |
| Project hooks before trust | Claude Code uses hooks from a repository's settings in a `claude -p` run, and when you trusted a parent folder whose trust extends to this folder. A nested repository needs its own trust in an interactive session. | [What runs before trust] |
| `disableAllHooks` | **Defined in:** any settings file. **Decided by:** the value left after precedence: the project's `.claude/settings.json` beats user settings, and `.claude/settings.local.json`, `--settings` and managed settings beat both. Discovery resolves it once across the user and project files and names the file that won. When the result is `true`, the hooks stay in the catalog with their source, have no active finding, and one gap names the unread higher-priority sources. When the winning value isn't a boolean, it is a gap and the hooks still count. Each `--config` file is resolved on its own. Reading `settings.local.json` is a separate alpha follow-up. | [disableAllHooks setting], [Disable hooks], [Local settings] |
| `apiKeyHelper` | Claude Code can use the command to obtain a credential for model requests and cache the result. During discovery, a project command overrides a user command. Both remain in the catalog with their commands withheld. Project helpers can run in `claude -p` or under inherited workspace trust. | [apiKeyHelper setting], [apiKeyHelper trust], [What runs before trust], [settings precedence] |
| `awsAuthRefresh`, `awsCredentialExport`, `gcpAuthRefresh`, `otelHeadersHelper` | For AWS, Claude Code runs `awsAuthRefresh` only if its credential check fails and `awsCredentialExport` at session start and on each credential reload. It runs `gcpAuthRefresh` when Google Cloud credentials expire or cannot be loaded, and `otelHeadersHelper` at startup and periodically for telemetry headers. Project helpers can run without a trust prompt in `claude -p` or when a parent folder's trust extends to this folder. Discovery marks a user command overridden when the project sets the same helper command. Explicit files are separate snapshots. Commands are withheld. Empty or non-text values are named gaps. | [AWS credential timing], [Local settings], [awsAuthRefresh setting], [awsCredentialExport setting], [gcpAuthRefresh setting], [otelHeadersHelper setting], [What runs before trust] |
| `processWrapper` | On macOS and Linux, Claude Code 2.1.210 or later can use `processWrapper` when it starts another Claude Code process, including a background session or a split-pane teammate. If you set `CLAUDE_CODE_PROCESS_WRAPPER`, Claude Code uses that launcher instead. Claude Code uses `processWrapper` only in user or managed settings. Project values are ignored. | [processWrapper setting], [Launcher coverage] |
| `sshHostCommands` | When you select a configured SSH connection to create a machine, Claude Desktop can run the connection’s `command` on your computer. Desktop connects to the host the command prints. Creating another machine for the same connection can run the command again. Claude Desktop reads `sshHostCommands` from your user settings or from a managed file or policy on your computer. Project values are ignored. Desktop requires a signed-in Claude account and version 3.6556.0 or later on macOS/Linux, or 4.16336.0 or later with OpenSSH on Windows. Stay-safe checks for duplicate IDs within the list and against `sshConfigs` in the same file. A malformed connection can affect whether other connections appear in Desktop’s environment selector. Desktop also checks command syntax and organization policy. | [sshHostCommands setting], [Desktop SSH limits] |
| `statusLine` | Claude Code can draw the status line by running a command after workspace trust. During discovery, the project command overrides the user command. When the files checked set `disableAllHooks` to `true`, discovery reports a gap. Project-local, command-line or managed settings can set it back to `false`. If it stays `true` through precedence outside managed settings, only a managed command can run. Explicit files are checked independently. | [statusLine setting], [Status line and file suggestion gates], [settings precedence] |
| `fileSuggestion` | Claude Code can suggest files when you type `@` by running a command after workspace trust. During discovery, the project command overrides the user command. When the files checked set `disableAllHooks` to `true`, discovery reports a gap. Project-local, command-line or managed settings can set it back to `false`. If it stays `true` through precedence outside managed settings, only a managed command can run. Explicit files are checked independently. | [fileSuggestion setting], [Status line and file suggestion gates], [settings precedence] |
| Other fields | Settings that change only how Claude Code looks or which model it uses are skipped without a gap. Other unsupported settings are inspection gaps. Only documented field names appear in the report; other names are withheld. | [Settings index] |
| File format | Settings files are JSON. `NaN`, `Infinity` and `-Infinity`, which Python's JSON reader accepts, are invalid values. | [JSON settings] |
